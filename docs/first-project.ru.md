# Первый проект с Agent Kit

[English](first-project.en.md)

Нужны Git и Python 3.11 или новее. [Стартовый AGENTS.md](../templates/project/AGENTS.md) хранится
в самом проекте. Если там уже есть такой файл, сравни оба и сохрани действующие правила проекта.

## Установить рабочий набор

Запусти команды из рабочей копии Agent Kit. В `project` укажи абсолютный путь к репозиторию,
а в `kit_ref` — полный SHA проверенного коммита. В новом репозитории без инструкций скопируй
шаблон из этого коммита. Заполни в нём правила проекта до первой задачи.

```bash
project=/absolute/path/to/project
kit_ref=FULL_COMMIT_SHA
git show "$kit_ref:templates/project/AGENTS.md"
# Посмотри вывод, затем скопируй файл в проект, если в нём ещё нет AGENTS.md:
starter=$(git show "$kit_ref:templates/project/AGENTS.md") &&
  (set -C; printf '%s\n' "$starter" > "$project/AGENTS.md")
```

Выбери скиллы, посмотри список изменений, затем установи и проверь их. С `--client both`
Codex и Claude Code используют одни и те же файлы.

```bash
python3 tools/skills.py select --project "$project" --ref "$kit_ref" --client both \
  --skill implement --skill implement-spec --skill code-review --skill tdd \
  --skill ship --skill pr --skill recap --skill diagnosing-bugs \
  --skill to-spec --skill to-tickets --apply &&
  python3 tools/skills.py preview --project "$project"
```

После успешного предпросмотра проверь список изменений и переходи к установке.

```bash
python3 tools/skills.py install --project "$project" &&
  python3 tools/skills.py check --project "$project"
```

[Как обновлять скиллы и работать с уже установленными копиями](distribution.md)

## Настроить доставку

- Для GitHub скопируй [шаблон PR](../templates/project/.github/pull_request_template.md)
  в `.github/pull_request_template.md` проекта и укажи его в `AGENTS.md`. Если в проекте уже есть
  шаблон, сначала сравни их.
- Чтобы включить классификатор, добавь `--skill owner-attention` к команде выбора скиллов.
  Скопируй [файл условий](../templates/project/docs/agents/owner-attention.md) в проект. В поле
  **Owner attention** в `AGENTS.md` укажи путь к условиям и скилл `owner-attention`. Заранее
  определи, в каких случаях нужно решение владельца и что оно разрешает. `ship` один раз
  вызывает свежего агента для работы только на чтение, после ревью и всех проверок проекта.
- Для каждой проверки возьми [шаблон манифеста](../templates/project/evidence-manifest.json)
  и сохрани его там, где проект хранит артефакты. Укажи SHA проверенного коммита или снимка
  дерева. Для каждого сценария запиши ожидание, наблюдение и результат `pass`, `fail`
  или `not_exercised`. Для каждого
  артефакта заполни `kind` (тип), `file` (путь от манифеста), `source` (источник данных)
  и `caption` (подпись). Добавь `url` после публикации по правилам проекта.

Снимок показывает состояние интерфейса, короткая запись — действие, таблица — данные или права
доступа. Перед прикреплением открой файлы и проверь, что они показывают и откуда взяты данные.
Для публичных материалов используй синтетические данные. Закрытые материалы храни там, где
их увидят нужные участники. Сценарии и важные ограничения оставь в тексте PR, технические
подробности помести под раскрывающийся блок.

## Пройти первую задачу

Возьми небольшое изменение с результатом, который видно через обычную команду или интерфейс
проекта. Учебный пример — команда состояния должна сообщить об отсутствующем входном файле
заданным текстом и завершиться с кодом 2. Запиши ожидаемое поведение до реализации.

| Шаг | Что сохранить |
| --- | --- |
| Постановка и старт | Задача, сценарий приёмки, исходный коммит, назначенная рабочая копия |
| Изменение и ревью | Результат тестов, проверенный коммит, выводы Standards и Spec, исправления |
| Проверка результата | Исправленный коммит, ожидание и наблюдение, материалы проверки и их ограничения |
| Доставка | Коммит доставки, результаты проверок, вопрос владельцу при необходимости, коммит после слияния |
| Уборка | Где лежат материалы, откуда восстановить изменение, какие ресурсы удалены и какие остались |

Поручи проверку свежему агенту, который не делал изменение. Он запустит обычную команду
на исправленном коммите, сохранит код выхода и вывод по `implement/VERIFICATION.md`.
Для исправления бага сохрани падение на старой версии и проход
на исправленной. Если сценарий требует недоступного аккаунта, браузера или сервиса, укажи
его в отчёте как непроверенный.

Один тест Agent Kit создаёт временный Git-репозиторий, устанавливает выбранные версии скиллов,
выполняет локальную задачу в отдельном worktree и проверяет результат после слияния и уборки:

```bash
python3 -m unittest discover -s tests -p test_project_starter.py
```

Этот тест использует локальный Git и вывод команды. Реальный CI, ревью агентами и приёмку
владельцем можно проверить на первой задаче в настроенном проекте, сохранив их результаты отдельно.
