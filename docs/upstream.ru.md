# Как обновлять скиллы Мэтта

У нас сохраняются три версии: принятый оригинал Мэтта, наши адаптации и выбранный
новый оригинал. Инструмент сравнивает их вместе. Это позволяет принять улучшения
Мэтта и сохранить наши правила совместимости. AI-first служит образцом устройства
адаптаций; его commit не подменяет SHA исходника Мэтта.

Сначала выбери точный полный commit источника и прочитай изменения. Предпросмотр
не меняет рабочие скиллы и принятую базу:

```bash
python3 tools/upstream.py update FULL_40_CHARACTER_MATT_SHA --stat
python3 tools/upstream.py update FULL_40_CHARACTER_MATT_SHA
```

Если есть конфликты, база не продвигается. Нужно разрешить смысловое расхождение
в собственной адаптации, сохранить его и повторить просмотр. Новые скиллы не
добавляются автоматически. Удаление заимствованного скилла требует отдельного разбора.

Для применения нужен чистый checkout и fingerprint из просмотренного предложения:

```bash
python3 tools/upstream.py update FULL_40_CHARACTER_MATT_SHA \
  --apply --expected-input FINGERPRINT_FROM_PREVIEW
```

Если исходные файлы или commit изменились, применение остановится. Ошибка записи
вызывает восстановление прежнего набора. Если само восстановление не завершилось,
инструмент сохраняет recovery по указанному пути; его нельзя удалять до разбора.

После применения проверяем библиотеку, diff и лицензии, делаем commit и независимое
ревью. Только затем публикуем версию. Каждый проект отдельно принимает нужные скиллы
на этом точном SHA по собственным правилам. Автоматического обновления всех проектов
при старте сессии нет.

[Полный технический порядок](upstream.md) описывает ограничения, блокировку обновления,
проверку дрейфа и восстановление. [Контракт процедур](engineering-contract.md)
объясняет границу общей библиотеки и проектного harness.
