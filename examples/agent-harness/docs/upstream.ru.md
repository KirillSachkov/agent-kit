# Сопровождение upstream

[English](upstream.en.md)

Репозиторий хранит редактируемые копии skills; запуск не требует загрузки другого репозитория.
Закреплённая версия Matt записана в одном месте: `provenance/upstream/mattpocock/SOURCE` в корне Agent Kit.
Начальные локальные адаптации получены через [ai-first-platform](https://github.com/KirillSachkov/ai-first-platform/commit/53c0b946506b41839e255806144c3289680061c8).

## Нетронутая копия

`provenance/upstream/mattpocock/skills.tar.gz` в корне Agent Kit хранит заимствованные skills точно в том виде, в каком они лежат в upstream на закреплённой версии, в раскладке upstream `skills/<group>/<skill>`. Архив сохраняет исходные байты и выводит эти `SKILL.md` из поиска скиллов. `SOURCE` хранит прежний хэш каталога, `ARCHIVE.json` описывает архив и каждый файл. Команды распаковывают его только в собственную временную папку.
Клиенты используют `.agents/skills` этого примера как ссылки на общий `skills/engineering`.
`SOURCE` записывает репозиторий, версию, дату и прежний хэш каталога. `scripts/check.py` падает, если распакованная копия не совпадает с этим хэшем. Корневой `NOTICE` Agent Kit называет текущую закреплённую версию. Прежние импортированные перечни остаются историческими источниками.

Посмотреть наши адаптации: `python3 scripts/upstream.py diff`, кратко `python3 scripts/upstream.py diff --stat`, при желании с именами skills.

Если мы переименовали заимствованный skill, строка `имя-upstream: локальное-имя` в `provenance/upstream/mattpocock/RENAMES` связывает его с оригиналом. Этот файл наш, он не входит в хэш копии. По нему `diff` и `update` находят локальную папку, а `check.py` проверяет, что есть и skill в upstream, и локальная папка.

## Выбор обновления

1. Создайте issue: изменение upstream, ожидаемая польза, границы и проверки.
2. Закоммитьте или сохраните незаконченные изменения в `skills/engineering` и `provenance/upstream` корня Agent Kit.
3. Запустите `python3 scripts/upstream.py update <revision>`. Скрипт скачивает upstream во временную папку и для каждого файла каждого заимствованного skill запускает `git merge-file`: наш файл, прежний upstream и новый upstream.
4. Разберите маркеры конфликтов и файлы из отчёта скрипта. Чтобы отказаться от изменения upstream, оставьте наш текст; разница станет видна как локальная адаптация.
5. Обновите корневой `NOTICE` Agent Kit, хэши актуального каталога и заметки об адаптациях, выполните проверки и проведите результат через PR. Исторические импортированные перечни сохраняйте без изменения.

Обновление переводит всю нетронутую копию на одну версию; исключений по отдельным skills нет.
Новые skills upstream скрипт перечисляет, но не добавляет. Если заимствованного skill нет в upstream, обновление останавливается до любых изменений.
Если обновление остановилось на середине, после проверки diff восстановите через Git только файлы этого обновления; шаг 2 делает это безопасным.
Совпадение хэшей подтверждает идентичность, а не качество.
Здесь нет запланированной синхронизации, update bot, submodule или установщика.

## Локальные адаптации

Начальные адаптации касаются доменных имён, проектных полномочий, committed review, проверки исправлений и доставки PR.
Этот репозиторий добавляет выбор языка и удаляет факты конкретного приложения.
`ship` создан локально; он не скопирован у Matt.
README skills содержит runtime pointers, уведомления, идентификаторы содержимого и список адаптаций.
При переносе upstream-предложений сохраняйте один источник проектной политики.
